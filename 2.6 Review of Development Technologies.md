# 2.6 Review of Development Technologies

This section reviews the software architectures and integration standards selected for the development of the system. The selection of these tools is grounded in established software engineering principles regarding scalability, maintainability, and data interoperability.

## 2.6.1 Web Application Frameworks (MVC Architecture)

Modern web development prioritizes frameworks that enforce logical structure to manage complexity. The Model-View-Controller (MVC) architectural pattern is the industry standard for this purpose.

**Theoretical Principles**
MVC decouples the user interface from the underlying business logic (Pop & Altar, 2014). This "Separation of Concerns" ensures that:
*   The **Model** manages data integrity and database interactions.
*   The **View** handles the presentation layer without containing complex logic.
*   The **Controller** orchestrates the flow of data between the Model and View.

**Justification for Adoption**
Frameworks adhering to MVC, such as Laravel, are favored in academic and commercial contexts because they facilitate Rapid Application Development (RAD). By standardizing the code structure, MVC frameworks allow for modular development, meaning features like "User Profiles" can be updated independently of the "Music Player" interface, significantly reducing the risk of regression bugs during the development lifecycle.

## 2.6.2 Microservices and Polyglot Programming

As web applications evolve to include advanced features such as Machine Learning, traditional Monolithic architectures often encounter performance bottlenecks. To address this, modern systems adopt Microservices principles.

**Polyglot Programming Strategy**
This approach supports "Polyglot Programming," which posits that different components of a system should be built using the language best successfully suited for that specific task.

*   **Web Service (PHP):** PHP is optimized for handling HTTP requests, session management, and server-side rendering, making it ideal for the core application logic.
*   **Computational Service (Python):** Python is the standard for data science. By isolating heavy computational tasks—such as Recommendation Algorithms using Singular Value Decomposition (SVD)—into a separate service, the system prevents blocking operations on the main web server.

## 2.6.3 API Integration and Data Aggregation Strategies

The system’s capability to discover and stream music relies on interoperability with external providers. This is achieved through RESTful Architectures and Multimodal Data Aggregation.

**RESTful Architecture (Spotify & YouTube)**
The system interfaces with streaming providers via Representational State Transfer (REST) APIs. Unlike older protocols like SOAP, REST relies on standard HTTP methods to ensure semantic consistency and statelessness:

*   **Stateless Communication:** Each request from the client to the server must contain all the information needed to understand and process the request. This is critical for scalability, as the server is not burdened with storing session state for API calls.
*   **Standardized Operations:** The use of GET (for resource retrieval) and POST (for resource creation) ensures that the system adheres to uniform interface constraints, allowing for predictable and cacheable interactions with external libraries like Spotify and YouTube.

**Security via OAuth 2.0**
To ensure user privacy and secure access to protected resources (such as private playlists), the system employs the OAuth 2.0 protocol. This industry-standard framework utilizes Access Tokens rather than sharing user credentials (passwords). Research indicates that OAuth minimizes security risks by limiting the scope and duration of access granted to third-party applications (Hardt, 2012).

**Metadata Enrichment (MusicBrainz & TheAudioDB)**
While commercial APIs provide streaming content, they often lack deep metadata. To resolve this, the system integrates open-source encyclopedic databases:

*   **MusicBrainz:** Utilized for Data Normalization. By relying on unique identifiers (MBIDs) rather than text strings, the system resolves ambiguities between artists with identical names, serving as a "ground truth" for the database.
*   **TheAudioDB:** Utilized for Metadata Enrichment. While commercial APIs provide streaming content, they often lack specific categorical data. The system integrates TheAudioDB to supplement the database with essential genre information, ensuring comprehensive categorization of music content that is often unavailable through standard commercial APIs.
